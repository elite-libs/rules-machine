Twelve finding families were reproduced and fixed on `security/deep-review-2026-10-14`, starting from main `ef4f3c5`. Final runtime changes are anchored at `252629f`: TypeScript source `6cf27cc`, Rust core/protocol `8176e25`, and Node bridge/wire `252629f`. The branch is for review; this run does not merge main, create issues/PRs, or publish a release. [Wayfinder ticket 09](../review/tickets/09-deep-security.md) and the [local PR draft](../review/prs/08-deep-security.md) track delivery.

The review examined untrusted JSON rules/data, supported JavaScript graphs, descriptor/prototype access, callback provenance, mutable-program validation, atomic writes, trace serialization, compilation/resource controls, Rust transport/cache/worker limits, distribution artifacts and dependency scope. Context matters: a host application supplying a live function/prototype is a different boundary from ordinary JSON input. Priorities below describe engineering impact, not formal CVSS scores or published advisories.

## Runtime and compatibility consequences

These fixes preserve ordinary JSON data and tested language domains while tightening host graphs and enforcing existing resource contracts. Writes to non-array JavaScript records carrying own iteration/tag symbols now reject. Atomic truncation of nonextensible arrays with removable slots rejects even if a later error has not yet occurred, because rollback must remain possible. Malformed public compiled metadata and malformed worker responses now reject consistently. Programs can still change between calls, while mutations through an input alias cannot rewrite the current executable structure.

Rust's resource accounting intentionally rejects heavy work that previously escaped the guard. It is not identical to TypeScript accounting, and the Rust implementation remains an explicitly limited experimental subset. Existing Rust performance claims for91ef65e are marked historical; the security build is measured separately.

The [cost report](PERFORMANCE.md) retains every workload slice and raw observation. Six paired blocks per language,84 observations each, found no clear aggregate throughput change: TypeScript 0.991× [0.899,1.083], native Rust 0.990× [0.852,1.142]. The initial eligibility regression flag did not replicate in a separate fixed12-pair confirmation,1.05× [0.80,1.37]. Both cohorts remain; these broad intervals cannot rule out meaningful costs, and the host was not isolated. Browser delivery grows1,753 raw bytes (+2.43%) and 440 gzip bytes (+1.99%); public declarations are byte-identical. No security check was removed to improve a score. No fresh bridge/browser latency or production performance neutrality is claimed.

## Remaining design and scope limits

- Cooperative TypeScript limits cannot preempt Proxy traps, arbitrary host callbacks, or an individual native operation such as JSON parsing, key enumeration or BigInt conversion. They are not a strict heap cap. Custom engines/resolvers/configuration and modified host intrinsics are trusted. Use caller-owned killable isolation when strict cancellation/memory isolation is required.
- Rust direct compilation is bounded by frame/per-expression/program limits rather than sharing the evaluation work counter. The legacy benchmark mode intentionally accepts repeated iteration counts and needs caller-owned cancellation. Arbitrary external Rc graphs remain outside its tree-input contract. The bridge owns timeout/abort termination but has no OS memory quota or implicit restart.
- Some combinator/error branches and host families remain outside the test inventory; the expert prototype enumeration is bounded. The conservative host-protocol write guard is not a claim to identify every object ever used as a prototype.
- A fresh read-only GitHub check confirms [alert 38](https://github.com/elite-libs/rules-machine/security/dependabot/38) remains open at moderate/medium severity for development esbuild in `examples/aws-lambda-service/package.json`. That standalone legacy example also targets an older published library. It needs a separately tested example/toolchain migration; this review does not claim the root audit covers it or dismiss the alert. [Exact scope](evidence/legacy-example-alert.json).
- Performance evidence is synthetic and noisy. Controlled deployment-relevant confirmation remains necessary before asserting zero overhead or a latency SLO. No production deployment/release occurred.
