# Independent expert review — current overhaul

Read-only review of expression engine, assignment scanner, language helpers, own-path utilities, structural executor, dependency parser, package configuration and focused tests. Probes were bundled with esbuild into `/tmp/rules-machine-council/expert-bundle.mjs`; replay script `/tmp/rules-machine-council/expert-probes.mjs`. No tracked files changed. Findings describe source at initial inspection; coordinator may subsequently repair them.

## Ranked actionable findings

1. **P1/P2: malformed literals can silently change a condition's meaning.** `createExpressionEngine().evaluateExpression('"true', resolver)` returns boolean `true`. `'"abc'` resolves input key `abc`, instead of rejecting an unterminated string. `validateSource` tracks a quote but never verifies it is closed; expressionparser tokenizer drops the opening delimiter at EOF. Checking unused RPN alone cannot catch it. Also `ABS()` becomes a term lookup for ABS (undefined normally, an attacker-supplied truthy input value if present), instead of an arity error. Reject unterminated literals/grouping and function calls with empty argument lists before dependency parsing. Ideally test malformed strings in actual if conditions and verify resolvers were never invoked. Severity depends on whether rule authors expect malformed rules to fail closed; the new test explicitly asserts this intent.

2. **P2 new own-path read/write mismatch.** With input `{'a.b':1,a:{b:10}}`, `ruleFactory('a.b += 2')(input)` leaves literal `'a.b'` at 1 but writes nested `a.b = 3`. `getOwnPath` checks exact own keys first, while `setOwnPath` always splits the path. Prior lodash.set uses castPath(path,object) and recognizes existing literal keys. Select `[path]` for an existing own exact path, with existing writable-path validation retained. This also affects array-rule set destinations and trace previous-value consistency.

3. **P2: compile accepts assignment targets the expression parser cannot evaluate.** Both `x[0] = 2` and `x["a"] = 2` pass keyPath validation but fail evaluation with unused RPN terms. The parser tokenizes brackets as ARRAY delimiters, not path access. This became visible with the new unused-RPN check. Either support writable literal bracket paths by parsing the RHS separately and resolving compound-assignment LHS explicitly, or reject them at compile time and narrow the path contract. `(x = 2)` meanwhile evaluates to 2 without assigning because metadata scans only top-level operators; decide whether nested assignment is prohibited and reject explicitly.

4. **P2: structurally invalid set destination produces side effects before rejection.** Input `{items:[1],x:0}`, rule `{map:'items',run:'x=1',set:'__proto__.p'}` throws Unsafe assignment path only after x becomes 1. Structural validator checks set is string, not that it is writable. Run assertWritablePath during preflight, and add a test with an earlier assignment plus malicious set to establish rejection before any mutation. The same applies to empty set string. Full transaction rollback for runtime errors is a different and much larger contract; not recommended as a prerequisite.

## Residual issues: distinguish scope from regressions

- **Dependency recursively mutates returned objects and executes zero-argument functions.** `ruleFactory('x')({x:{a:()=>42}})` changes x.a into 42 in caller input. Reading `Object.freeze({a:1})` throws a TypeError. Reading a cyclic object/array throws RangeError. expressionparser's isBasicDataObject rejects normal Object.prototype due to its built-in methods, routing ordinary objects through classObjEvaluator assignment. This predates the cache; avoid claiming that expressions are pure, that arbitrary object values are supported, or that all inherited/function execution is eliminated. A focused follow-up could normalize only internal thunks without traversing input objects, but this needs careful compatibility design.
- **Limits do not form a general execution sandbox.** A flat 6000-term addition fits source-length and nesting bounds but overflows recursive parser/evaluator stack. Nested map rules can multiply work despite 10000 static nodes. Existing bounded RANGE/GCD/ISPRIME repairs are useful, but no total operation/allocation budget exists. Document residual trust/isolation requirement; a wall-clock Promise timeout cannot interrupt this synchronous work. The flat-chain probe terminated in well under one second; no heavy denial-of-service workload was run.
- **Multiline expression whitespace is not recognized by dependency grammar.** `true\nAND\nfalse` resolves as one unknown term rather than boolean syntax; malformed operator-only tails mostly do reject with the new RPN check. Specify whitespace if multiline sources are supported.
- Structural object validation uses enumerable keys but dispatch uses own properties including nonenumerable ones; hostile JS descriptors/getters can defeat preflight. This is not a JSON-program vulnerability and should not distract from the concrete JSON-path fixes above.

## Verified/rejected concerns

- Cached syntax uses late activeResolver dispatch and restores previous resolver in finally. Same-engine synchronous nested evaluations, exceptions, and normal mutable array-literal evaluation have credible dedicated tests. No cache-specific stale-context or array-state leak identified.
- Comma operator now concatenates rather than pushes into cached argument arrays; literal result arrays are newly materialized. SORT/REVERSE operate on copies.
- No reproducible global Object.prototype pollution or RCE established. New writes reject prototype/constructor/__proto__ segments, avoid inherited traversal, and dictionary construction uses defineProperty. Do not elevate local returned-object hazards to global pollution without evidence.
- Browser packaging uses an IIFE bundle, platform browser, global performance and no external runtime modules. Both Node distributions bundle expressionparser, preserving the null-evaluation patch downstream. Existing packed ESM/CJS/browser-global smoke checks target the relevant risk. No new packaging blocker found.
- Preflight handles null/unknown/ambiguous rules, cycles, sparse rule arrays, plain/null prototypes, recursive logical shape, and depth/node limits. Nested return signals and array callback context finally restoration are sound for normal JSON inputs/rules on inspection.
