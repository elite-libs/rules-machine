# Architect + Detail Detective: read-only review

Source reviewed: current src/{index,types}, structural executor/types, expression engine/language/helpers, unit tests, README, guide/examples, REVIEW_2026. No source edits. Findings below initially established directly from source; executable reproductions pending dependency setup.

## Priority findings and concrete repairs

1. **P1: nested logical rules silently skipped.** `AndRule`/`OrRule` explicitly permit recursive logical nodes, and docs/guide.md demonstrates nested access checks. Executor's and/or loops evaluate only strings; object children are ignored. E.g. `{if:{and:['true',{or:['false']}]},then:'allowed = true',else:'allowed = false'}` grants access. Fix one recursive evaluator for strings/and/or with short-circuiting; empty AND true, empty OR false. Top-level AndRule/OrRule are also included in public Rule union yet ignored: either support or remove from public union with explicit validation/error.

2. **P1: return does not stop enclosing execution.** `handleRule({return:...})` emits BREAK but if/try callers discard the result; nested Rule[] maps also discard it. E.g. `[{if:'true',then:{return:'1'}},{return:'2'}]` returns 2. Also `['"BREAK"','x = 2']` stops accidentally due to string sentinel collision. Fix private symbol/tagged control signal propagated by every structural handler, with explicit array callback semantics. Prefer array `run` return to finish the callback only (useful conventional behavior); document/test this boundary. Rule[] currently returns mapped results even for sequences, so changing its final-value semantics needs compatibility consideration separately.

3. **P1: array context leaks and nested loops corrupt outer scope.** Object.assign(input, {$item,$index,$array}) is never restored, including exceptions. Reusing the same input after a map throws reserved-key validation. Nested arrays leave inner $item in the outer callback and later expressions read wrong values. Fix save/restore in try/finally around each callback or a separate lexical scope resolver; lexical scope avoids adding internals to trace/input but is a larger change. Preserve assignment mutation of caller input.

4. **P1: assignment detection scans literals, requires spaces, picks operator by fixed list rather than source position.** engine.compile uses includes(` ${op} `), split(op). A plain string literal `"hello = world"` is marked assignment; assignment containing string `x += " = "` chooses '=' inside literal; compact `x=1` parses but does not mutate. Fix scanner aware of quotes/escapes/groups that recognizes only one supported assignment at top level and validates lhs. Do not regex-rewrite inside string literals. Add missing %= only if intentional; guide currently promises it but language lacks implementation.

5. **P1/P2: reachable synchronous nontermination.** ISPRIME(INFINITY) loops forever; GCD(INFINITY,1), GCD(0 / 0,1) never terminate; RANGE(1,INFINITY) allocates indefinitely. Numeric domain checks can eliminate these without a large generic sandbox design. Also RANGE with large finite numbers such as 2^53 stops incrementing, even if bounds are finite. Require safe integer finite bounds/count budget for RANGE; finite integers for GCD; finite integer primality with iteration budget or documented trusted input scope. Generic Promise timeout does not interrupt synchronous execution.

6. **P2: incorrect numerical functions.** COSH calls Math.cos. ISPRIME returns true for zero, negatives, nonintegers (val !== 1 after divisor loop). Tests COSH(0) and only ISPRIME(17/15) miss it. Fix exact math/domain checks, verify COSH(1), ISPRIME(-1/0/1/2/2.5).

7. **P2: inherited property resolution and object dictionary prototype hazards.** lodash.get permits reading inherited constructor/toString paths, despite shallow input blacklist. DICT and UNZIPDICT assign into `{}` with arbitrary keys, so '__proto__' changes returned object's prototype. PUT's Object.assign({}, inputObj, {[key]:value}) can trigger __proto__ setter from JSON-parsed inputObj (computed final source also has enumerable own key), producing polluted returned object. This does not by itself establish global Object.prototype pollution or RCE. Prefer define-own-property/safe dictionary construction preserving normal object API; validate path access/write policy at boundaries rather than recursively rejecting all domain data containing names like constructor.

8. **P2: broken literal helper.** trailingQuotes regex uses global state and replaces the whole literal with empty string (rather than stripping endpoints). extractValueOrLiteral({}, '"abc"') returns ''. Subsequent invocations can alternate due to lastIndex. isBoolean uses `in` on an array: 'true' is false; '2', 'length' are true, producing nonsensical autoDetectType('2')=false. Tests explicitly preserve this bug; correct expectations need replacement, not added mirrored coverage. isNumber accepts '..', '1.2.3'.

9. **P2: null is treated as missing.** extractValueOrLiteral tests `value != null`; termResolver repeats lookup using ??, so strict ignoreMissingKeys:false throws on explicit input null. Use undefined/existence checks consistent with advertised missing semantics. evaluateRule local ignoreMissingKeys parameter is unused by resolver, so purported local return leniency is dead code.

10. **P2: malformed structures silently no-op or throw incidental native errors.** Unknown {}, ambiguous combined operator objects, logical objects at top level ignored; null reaches `in` operator and throws TypeError. Build explicit schema/dispatch validation with actionable UserError, preferably factory-time to fail before partial input mutations. Avoid rejecting untrusted depth only after recursive descent; cycles need visited-set if JS objects allowed.

11. **P2: trace changes behavior and is expensive without trace.** serialize(previous), serialize(input), currentState executed inside logTrace argument construction even when trace false in many handlers. Cyclic input crashes ordinary assignment; BigInt in otherwise unused input also crashes. Catch logs serialize unconditionally and can replace original error. Gate collection/serialization before evaluation; specify trace snapshots safe for cycles/BigInt if arbitrary Record input is supported. Trace.expression.result holds raw references, so later mutation can rewrite historical result rows. returnValue stays initial input unless explicit return while lastValue is actual final result; clarify contract.

12. **Packaging/API mismatch.** node:perf_hooks import, platform:'node'/node24 target and external deps conflict with browser/edge support claims and browser IIFE field. Use globalThis.performance, explicit tested browser build bundle; inspect generated artifact in isolated HTML with no require. createRuleExecutor/createExpressionEngine are documented public interfaces by comments but values not exported root; deliberate API choice required. ruleFactory output TReturn | ExecutionResult regardless literal trace true/false forces casts; overloads can reflect options without runtime change.

## Compatibility and rejected remedies

- Existing audit is stale (v1.6, Jest/ESLint paths) and mixes speculative security claims with facts. Current code uses Vitest/Biome and split engines. Do not carry over 'critical outdated dependency' or RCE statements without current advisory + executable reachability evidence.
- lodash.set blocks prototype/constructor/__proto__ path traversal already. Deep blacklist of all input data is intrusive and fails to address dictionary creation or inherited reads. Prototype pollution needs exact exploit and scope rather than a broad scanner claim.
- FILTER_VALUES/INCLUDES_VALUES implement exclusion despite helper comment suggesting inclusion. Existing public snapshot explicitly expects exclusion (London/Milan removed). Preserve behavior or introduce separately named include function plus clear deprecation; do not silently reverse semantics.
- DATE('1year') is not duration because length<6 dispatch; unknown short text silently resolves to now. DATEISO odd inputs yield UnknownDate strings. Needs explicit documented date/duration contract; caching relative DATE strings would break semantics.
- TAKEWHILE/DROPWHILE call predicate before checking i<arr.length, so empty/all-matching inputs run predicate on undefined and throw. Swap bounds check first. Distinct from speculative parser nested-array support.
- Expression term delegate uses parseFloat, accepting partial numeric tokens '123abc' as 123; strict numeric token grammar needed. Check scientific notation and negative literals compatibility before tightening.
- Arithmetic '+' intentionally requires numbers; docs using string concatenation and unsupported RAND()/MATCH()/&&/object-return examples should be executed as documentation tests or corrected.
